# 質問構成と編集方針

見直し日: 2026-10-24

## このチェックで届けるもの

利用者が設定や運用を振り返り、「次に何をするか」「誰に何を聞くか」を選ぶための自己点検です。端末やサーバーのスキャン、侵入の検出、脆弱性の実証、安全性の認定は行いません。個人情報、URL、IPアドレス、パスワードなどの実値を入力させない構成とします。

攻撃者によるAIの利用は、詐欺の見分けにくさや自動化を増します。質問の構成では、AIだけを独立した万能の脅威として扱わず、侵入の入口、アカウント、データへのアクセス、検知、復旧を合わせて点検します。これは本アプリの編集上の整理であり、公的機関による認定や推奨を受けた診断ではありません。

## 4コース、各40問

既存のデータは個人・管理者・開発者の各40問、合計120問でした。各コースの40問という長さを維持し、技術運用の担当を独立させ、合計160問に再構成しています。利用者が全160問に答える設計ではありません。

| コース | 答える人 | 確認すること |
| --- | --- | --- |
| personal | PC・スマホを使う個人、ご家庭 | 更新、アカウント、偽の連絡、バックアップ、アプリ・AI、家庭の機器、相談先 |
| admin | 経営者、総務、チームの非技術管理者 | 責任と分担、社員の利用ルール、取引詐欺、委託先、バックアップの確認、緊急連絡 |
| it | システム・社内IT・インフラの担当者 | 資産と公開範囲、VPN・境界機器の更新、認証、横展開の抑止、ログ、隔離、復旧 |
| dev | アプリ・API・AI機能の開発者 | 秘密情報、依存関係とCI/CD、認証・認可、入力処理、データ保護、AIの権限と出力、検証 |

同じテーマでも、管理者には「実施する担当と報告があるか」、システム担当には「設定と動作を検証したか」を問います。管理者コースに製品設定や技術用語を過度に持ち込みません。複数の役割を兼ねる方は、必要なコースを別々に利用できます。

## 重要12問から、希望者は40問へ

最初は各コースの重要な12問で結果を表示します。更新、認証、詐欺への対応、権限、バックアップ・復元、初動などを、その立場で確認できる内容から選んでいます。
12問という件数や選定は、本アプリの利用負担を抑えるための編集判断です。CISAやCISが定める公式な12問チェックリストではありません。

結果の「残り28問も確認する」から、最初の回答を引き継いで40問の確認へ進めます。問題の並びは重要12問を先にし、その後に残り28問を元の順序で置きます。
12問の結果には残り28問を含めず、画面とレポートに確認範囲を明示します。40問まで完了すると、12問を含む40問全体を集計します。
自己チェックの対策済み割合と、別機能の知識チャレンジの合否・得点は混同しません。

## 見直しで重視したこと

- AIによる音声・映像・自然な文章のなりすましには、登録済みの連絡先など別経路で確かめる行動を問う。
- 偽の人間確認・エラー解決でコマンドを貼り付けさせるClickFixを、個人と組織の双方へ含める。
- MFAとパスキーを勧めながら、端末感染や盗まれたセッションまで防げるとは説明しない。セッション失効とアカウント復旧を別に扱う。
- ランサムウェアへの備えはコピーの有無で終えず、同期との差、削除されにくい保管、権限分離、復元テストまで扱う。
- 公開入口、VPNなどの境界機器、悪用中の脆弱性、サポート期限、委託先の接続を優先して点検する。
- AI連携の権限、重要操作の承認、プロンプト注入の影響制限、RAGの認可、出力の検証を含める。
- 開発者の基本対策として、認可の漏れ、セッション、SQLインジェクション、XSS、CSRF、SSRF、アップロード、CI/CDと依存関係を維持する。
- 事故の早期報告を責めない運用と、連絡・復旧の準備も対策として扱う。

従来の「HTTPSなら本物」「VPNがなければ常に平文」「OS標準の保護では不十分」「退会で全データが即時物理削除される」「CORSのワイルドカードは用途を問わず危険」と受け取られうる説明は修正しました。定期的な利用者パスワード変更を一律に求める質問や、知識・性格を責める質問は置いていません。

## 質問の書き方

1. 「はい」が対策を確認できた方向になるよう統一する。否定疑問と二重否定を避ける。
2. 1つの主要な対策を問う。複数の手順は、その対策を確かめる説明・助言へ置く。
3. 個人コースは製品名や専門用語より、設定の場所と行動が分かる言葉を優先する。
4. 「わからない」は失敗や危険の判定ではなく、設定・担当者へ確認する状態とする。
5. 「対象外」は、該当する機能・環境を使っていない場合に限る。対策をしていないことを対象外としない。
6. 助言は、最初に進める具体的な行動を示す。高額な製品購入や専門家への依頼だけを解決策にしない。
7. 事実確認を伴わない「安全」「侵入されている」「最高危険度」などの断定を避ける。

## データと結果の扱い

質問は `data/questions.json`、出典は `data/sources.json` に分けています。質問のIDはコース内で固定し、並び替えだけで変更しません。既存質問と意味が変わった今回の改訂前後の結果は、同一尺度として比較しないでください。

| フィールド | 役割 |
| --- | --- |
| lane / id | コースと一意の識別子 |
| category | 進行中に表示するまとまり |
| question / description | 質問と短い補足 |
| adviceTitle / adviceText | 見直し・確認のための行動 |
| priority | high: 優先して確認、medium: 次に取り組む、low: 少しずつ整える |
| optional | 機能・環境により「対象外」を選べる場合のみtrue |
| sourceIds | 出典一覧のIDとの対応 |
| references | sourceIdとsectionで、実際に対応する節・対策番号を示す |
| quickCheck | 各コース12問のみtrue。標準チェックへの採用を示す |
| deductPointsOn / points | 旧形式との互換用。NO、high=3 / medium=2 / low=1で保持 |

優先度と重みは本アプリの編集上の目安です。公的な評価点、被害確率、CVSSではありません。現在の結果表示は旧形式の減点式の「安心度」やA/B/Cの評価を使いません。

対策済みの割合は、自己申告で「はい」と答えた件数を、対象外を除く質問数で割った割合です。「わからない」も対象項目には含まれますが、見直したい項目と分けて件数・行動を表示します。100%でも、対象範囲外の問題や未認識の問題がないことを保証しません。

結果の行動は優先度順に並べ、同じ優先度では「見直したい」「未確認」の順に表示します。未確認には、まず設定や担当者へ確認する案内を付けます。質問の `points` を結果割合の重みには使いません。

## 出典の読み方

質問は一次資料を参考に本アプリ向けに新しく記述したもので、出典の原文や公式診断票の転載ではありません。`sourceIds` は、背景・対策の根拠を確認するための対応であり、文面の完全一致や公式の採点基準を意味しません。

主要な基盤は次の資料です。個別の開発対策にはOWASPの各Cheat Sheetを対応づけています。

- [NIST CSF 2.0 Small Business Quick-Start Guide](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=957322)
- [NZ NCSC ClickFix注意喚起](https://www.ncsc.govt.nz/alerts/compromised-websites-serving-clickfix-pages/)
- [OWASP ASVS 5.0](https://asvs.owasp.org/)

2026-10-24の見直しでは全160問に172件の参照箇所を対応づけ、すべての質問に米国または国際的な一次資料を少なくとも1件含めています。日本の公的資料も、国内の状況を理解するために併用します。
出典のkindはgovernment（政府・公的機関）、standard（公開基準・技術資料）、vendor（企業の対策資料・攻撃調査）です。現在44資料を20・20・4件に分類しています。

公開基準は対策の構成と根拠、企業の実施チェックリストは確認すべき運用、攻撃調査は新しい侵入経路を見落とさないために使います。特定の企業の製品購入を対策済みの条件にはしません。
M-Trendsの調査対象はMandiantが調査した事案であり、その割合を一般企業や個人全体の危険率へ置き換えません。パスキーを口実にした詐欺も、パスキーの暗号が破られたという意味にはしません。
CIS v8.1の隔離バックアップ（11.4）はIG1ですが、復元試験（11.5）はIG2/3です。復元確認を本アプリで重視する判断と、IG1への所属は分けて記載します。
セッション失効はID基盤の停止だけで即座にすべてのアプリCookieが無効になると説明せず、アプリ側のセッション取り消しと検証を含めます。

LLM資料は、公式プロジェクトが公開する2026版ソースを参照しています。ほかの公式ページに2025版の表示が残る場合があるため、版と公開状態を明示した資料を優先します。CISAの一部ページは取得時にアクセス制限がありましたが、検索で確認できた公式ページおよび公式配布資料を参照しています。

## 更新と確認の手順

- 少なくとも四半期ごとに、一次資料の更新・移転・サポート条件を確認する。自動更新される診断ではないため、見直し日を実際の確認なしに進めない。
- IPAの年次更新、認証指針の改訂、広く悪用される新しい侵入経路などが出た場合は、定期の見直しを待たず影響を確認する。
- 特定のCVEや製品バージョンを質問文に固定しすぎず、メーカーの情報と悪用状況で判断する習慣を問う。緊急情報は公式資料へ案内する。
- 改訂時は「コースの難度」「YESの方向」「対象外の条件」「最初の改善行動」「出典の対応」を確認する。
- JSONの構文、一意のID、各コース40問、必須フィールド、優先度、出典IDとHTTPSリンクを検証する。
- 各コースの重要12問、referencesの参照先、出典のkind、12問から40問への回答引継ぎも検証する。
- 旧IDの意味、優先度、対象外条件が大きく変わる場合は、変更内容を記録し、結果の単純比較を避ける。
- 新しい質問を加える場合は40問に追加し続けず、重複や優先度の低い質問との入替えを検討する。
