# セキュリティのいまを知る

登録不要で、立場に合わせた重要12問から始めるセキュリティ自己チェックです。希望する方は回答を引き継いで40問まで続けられます。
個人・ご家庭、会社・チームの管理者、システム担当者、開発者・AI開発者の4コースがあります。
PC・スマホの設定から、組織の運用、公開システム、AIアプリの設計まで、それぞれの担当範囲を確認します。

## 起動

Node.js 22以上で、このフォルダーから実行します。追加パッケージのインストールは不要です。

```sh
npm start
```

表示された `http://127.0.0.1:8787` をブラウザで開きます。終了はターミナルで Ctrl+C。
HTMLをダブルクリックする `file://` では質問JSONを読み込めないため、HTTPサーバーを利用してください。
静的HTTPSホスティングでも、`index.html` と `css/`・`js/`・`data/` を同じ構成で配信すれば動きます。
ローカルプレビュー用サーバーは127.0.0.1だけで待ち受けます。

## Cloudflare Workersへの公開

公開フォルダーは `dist/` です。`npm run build` で、アプリが使うHTML・CSS・JavaScript・JSONの10ファイルだけを出力します。
`wrangler.json` がこのフォルダーを指定します。リポジトリ全体の `.` を公開フォルダーに指定しないでください。
`node_modules/` にはWrangler自身の大きな実行ファイルが含まれ、Workersの1ファイル25 MiB制限で失敗する原因になります。

Git連携したWorkers Buildsの設定は次のとおりです。

| 設定 | 値 |
| --- | --- |
| ルートディレクトリ | この `package.json` と `wrangler.json` があるフォルダー（リポジトリ直下なら空欄または `/`） |
| ビルドコマンド | 空欄（次のデプロイコマンドの先頭でビルドする） |
| デプロイコマンド | `node scripts/build.cjs && npx wrangler deploy --config ./wrangler.json --assets ./dist` |
| Worker名 | `security-diagnostic-tool`（`wrangler.json` と一致させる） |

設定とソースをGitリポジトリへ反映してから再ビルドしてください。`dist/` はビルドで生成するためGitには含めません。
ビルド環境が自動生成した `wrangler.jsonc` に `assets.directory: "."` が残っている場合は、このプロジェクトの `wrangler.json` に統一してください。
`wrangler deploy` だけでは、このプロジェクトの `npm run build` を代わりに実行しません。

Cloudflareのログで `Detected Project Settings` とともに `Output Directory: .` が表示され、新しい `wrangler.jsonc` が自動生成される場合は、実行場所で修正済みの設定が見つかっていません。
連携ブランチの `wrangler.json`、`scripts/build.cjs`、更新した `package.json` をGitHub上で確認してください。PC内の編集はGitHubやCloudflareへ自動反映されません。
コマンドの `--config` と `--assets` で設定ファイルと公開フォルダーを明示し、不足があればリポジトリ全体を公開せず停止するようにしています。
成功時は、デプロイの前に `Built 10 public files in dist/` と表示されます。

CLIで公開する場合は、Cloudflareへの認証を済ませてから `npm run deploy` を実行します。このスクリプトは先にビルドします。
通常のアプリ実行・ビルドに追加パッケージは不要ですが、公開時には `npx` がWranglerを取得する場合があります。

Cloudflare Pagesを選ぶ場合も、ビルドコマンドは `npm run build`、ビルド出力ディレクトリは `dist` です。PagesのGit連携では上記Workers用のデプロイコマンドは設定しません。

参考：[Workers Buildsの設定](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/)、[静的アセットの公開フォルダー](https://developers.cloudflare.com/workers/static-assets/binding/)。

## 質問と結果の設計

- 各コース40問、合計160問。最初は重要12問だけで結果を表示し、希望する方は残り28問へ進めます。
- 12問と40問の結果・レポートは確認範囲を区別します。12問の結果に未回答の28問は混ぜません。
- 「はい」はすべて対策済みの意味。「いいえ」「わからない」を分けて結果に表示します。
- 回答を選ぶと自動で次の質問へ進み、最後の回答で結果が表示されます。「前の質問」で戻って修正できます。
- 環境によって使っていない機能は、その質問で許可された場合だけ「対象外」を選べます。
- 「対策済みの割合」は はい ÷（全項目 − 対象外）。侵入確率や安全度を表しません。
- 改善項目は質問の重要度を優先し、同じ重要度なら「いいえ」を「わからない」より先に表示します。
- 最初に3項目を示し、全項目の対策と出典も確認できます。回答修正・コピー・テキスト保存に対応します。
- 各質問の参考資料に、対応する公開基準の節や対策番号を表示します。政府・公的指針、公開基準、企業の対策資料・攻撃調査を区別します。

実際の機器の脆弱性、マルウェア感染、侵入の有無を検査するツールではありません。
回答がすべて「はい」でも安全性を保証しません。質問の構成と見直し方針は [docs/QUESTION_DESIGN.md](docs/QUESTION_DESIGN.md) に記載します。

## セキュリティ基礎チャレンジ

自己チェックとは別の、20問4択の知識テストです。ネットワーク、Webとアクセス制御、安全なWeb開発、運用と復旧の4分野・各20問、計80問を用意し、毎回各分野から5問ずつ抽選します。
1問5点、100点満点で、90点以上（18問以上正解）を「合格」、90点未満を「不合格」と表示します。
未回答の問題を除外して得点を上げることはなく、全問の回答後に採点します。

回答を選ぶと自動で進み、前の問題に戻って回答を直せます。再挑戦時は問題の組み合わせと選択肢の順番が変わります。
未出題を優先して最初の4回は80問を重複なく出題し、一巡後も直近2回の問題を避けます。途中でやめた挑戦も抽選済み20問を履歴に含めます。
結果では正誤・選んだ回答・正解・解説・出典と、分野ごとの成績を確認できます。
これは本アプリが定めた学習用の合格基準で、公式資格の認定や、実務技能・環境の安全性を保証する試験ではありません。
問題と採点は `data/challenge.json`、`js/challenge-engine.js`、画面は `js/challenge.js` で管理します。詳細は [docs/CHALLENGE.md](docs/CHALLENGE.md) に記載します。

## 画面と操作

白と緑を基調に、端末・チーム・サーバー・開発画面の独自SVGイラストでコースを見分けられます。
質問では分野のアイコン、回答を表すアイコン、回答済みと現在位置がわかる進行マークを表示します。
結果は内訳のアイコンと図、知識チャレンジは学習・達成・復習のイラストで内容を補います。
回答は自動で次へ進み、選択時と画面の切り替わりには短いアニメーションを付けています。端末の「動きを減らす」設定に対応し、常時繰り返す動きは使いません。
イラストはHTML内のSVGを共有して描画し、外部画像・フォント・アニメーション用ライブラリーの読み込みはありません。

## プライバシー

回答と得点はブラウザのメモリー内だけで処理し、送信・自動保存しません。Cookie・解析タグ・外部フォント・外部ライブラリーは使いません。
知識チャレンジの重複回避に限り、出題した公開問題IDをlocalStorageへ保存します（現行バンク数の80ID以内）。回答・得点・正誤・個人情報は保存しません。
開始画面で出題履歴をリセットできます。保存できない場合も、同じページを開いている間はメモリーの履歴で動作します。
再読み込み・タブを閉じる操作で回答は失われます。自分でコピー・保存したレポートは端末に残ります。

ページ、スクリプト、質問と出典のJSONを読み込む通信はあります。公開ホスティングのアクセスログにはIPアドレスなどが残る場合があります。
出典リンクは自分で開いたときに外部サイトへアクセスします。回答をURLに付ける処理はありません。
「データ送信0バイト」のような表現は使っていません。

## 開発・確認

```sh
npm test
npm run check
```

`js/diagnostic.js` が質問スキーマ・回答集計・レポート生成、`js/app.js` が画面操作を担当します。
質問は `data/questions.json`、出典と見直し日は `data/sources.json` で管理します。
`points` と `deductPointsOn` は既存データの互換のため保持しますが、点数の減算による安全ランクは使用しません。
